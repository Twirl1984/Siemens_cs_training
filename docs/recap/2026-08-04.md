### K3 · `<Nullable>enable</Nullable>` ist in beiden Projekten gesetzt — trotzdem steht jetzt ein Guard in `GreetingService.Process`. Warum reicht der Schalter nicht?

<details><summary>Antwort</summary>

**Belegt am eigenen Code (A4.3):** Der Aufruf `_sut.Process(null!)` kompiliert warnungsfrei —
`null!` schaltet die Prüfung ab. Ohne Guard war der Testlauf rot mit:

```
Assert.Throws() Failure: Exception type was not an exact match
Expected: typeof(System.ArgumentNullException)
Actual:   typeof(System.NullReferenceException)
```

**Die Entscheidung (R3):** Guard einbauen — `ArgumentNullException.ThrowIfNull(args)`, weil
`Process` eine öffentliche API-Grenze ist. NRT prüft zur Compilezeit und nur in Code, der
selbst mit aktiviertem Schalter gebaut wird; `null!` beweist, dass die Prüfung umgehbar ist.
`ArgumentNullException` benennt den schuldigen Parameter, `NullReferenceException` sagt nur,
dass *irgendwo* etwas null war.
