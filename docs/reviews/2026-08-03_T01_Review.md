## Befunde

### Was trägt

- **Result-Pattern** statt Exception-Steuerung: `GreetingResult` als `sealed record` mit
  `Success`/`Error`-Factories. Für Tag 1 eine überdurchschnittliche Designentscheidung.
- **`Program.cs` auf 7 Zeilen reduziert**, reine I/O + Exit-Code. Die Trennung sitzt.
- **Testnamen idiomatisch**: `Process_ReturnsError_WhenNoArgumentIsProvided` — Muster
  *Methode_Erwartung_Bedingung*. `_sut` als Feldname zeigt Fachvokabular.
- **Mutationsprobe bestanden.** Vier künstlich eingebaute Fehler, alle vier von den Tests gefangen:

  | Mutation | Ergebnis |
  |---|---|
  | `IsNullOrWhiteSpace` → `IsNullOrEmpty` | 1 Test rot ✅ |
  | Fehler-ExitCode 1 → 2 | 3 Tests rot ✅ |
  | `args.Length == 0` → `< 0` | 1 Test rot ✅ |
  | Zahlen-Regel entfernt | 1 Test rot ✅ |

  Die Tests sind echt, kein Placebo. Das Abnahmekriterium ist damit belegt.

### Was zu korrigieren ist

**1. Der Whitespace-Test zementiert einen nie getroffenen Entschluss**

```csharp
Assert.Equal("Hallo,   Linus  !", result.Message);   // GreetingServiceTests.cs:56
```

Der Test hält fest, *dass* nicht getrimmt wird — aber diese Entscheidung wurde nie gefällt.
Ein Test soll das Soll-Verhalten festschreiben, nicht das Ist-Verhalten protokollieren.
Entweder trimmen (dann Test anpassen) oder bewusst nicht trimmen (dann im Testnamen begründen).

**2. Die Zahlen-Regel verletzt ein Abnahmekriterium**

`dotnet run -- 123` gab vorher `Hallo, 123!` mit Exit 0, jetzt `Der Name muss ein Text sein.`
mit Exit 1. Der Auftrag forderte ausdrücklich unverändertes Außenverhalten und listete
Erweiterungen unter *Nicht gefordert*. Die Idee kam laut Bildspur (10:10) selbst, nicht vom
Assistenten — also eigene Entscheidung, nicht KI-Übergriff. Trotzdem Scope-Bruch.

**3. `double.TryParse` ist die falsche Prüfung — und kulturabhängig**

Gemessenes Verhalten auf diesem Mac (de-DE):

| Eingabe | Ergebnis |
|---|---|
| `123` | abgelehnt |
| `1,5` | **abgelehnt** (Komma = deutscher Dezimaltrenner) |
| `NaN` | **abgelehnt** |
| `Infinity` | **akzeptiert** → `Hallo, Infinity!` |

`double.TryParse` verwendet ohne Angabe die `CurrentCulture`. Auf einem CI-Runner mit
en-US-Locale kehrt sich das um: `1.5` wird abgelehnt, `1,5` durchgelassen. **Dasselbe Programm
verhält sich auf einem anderen Rechner anders — und die Tests decken das nicht auf.**
Wenn die Regel bleiben soll: `CultureInfo.InvariantCulture` explizit angeben, oder besser
über die tatsächliche Anforderung entscheiden (`name.All(char.IsDigit)`? Warum ist `NaN`
kein Name, `Infinity` aber schon?).

**4. Das Repo ist nicht klonbar-baubar**

Frischer Klon von `c79b7e9` enthält nur fünf Dateien. Es fehlen `SiemensPrep.slnx`,
`src/Hello/Hello.csproj` und `.gitignore` — `dotnet build` scheitert mit `MSB1003`.
Der Agent hat den Commit selbst gesetzt und dabei selektiv `git add` gemacht.

**5. `IsSuccess` und `ExitCode` sind redundant**

Zwei Quellen der Wahrheit für denselben Sachverhalt. Jeder Test prüft beide. Eine davon
könnte abgeleitet sein (`IsSuccess => ExitCode == 0`).
